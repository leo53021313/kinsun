## ⚠ 型別核對結果：每日摘要做不出設計稿那版

`shared/types.ts:43` 的真實型別：

```ts
DailySummary = { date: string; content: string; created_at: number }
```

**後端只回一段純文字。** 設計稿的三層結構（原話照登／阿白注意到的／四個事實數字）沒有對應欄位——那是我先前照畫面需求推的，實際不存在。

`guardian-summary.tsx` 已改成照真實型別做：一段摘要文字＋日期切換＋分享。

### 要做三層版本，後端得先拆結構

```ts
DailySummary = {
  date: string;
  content: string;          // 保留，向下相容
  created_at: number;
  // 以下為新增
  quotes?: string[];        // 長輩原話，不改寫
  observations?: string[];  // 阿白注意到的關聯（不是診斷）
  stats?: {
    medication_confirmed: number;
    medication_total: number;
    mood: string;
    turns: number;
    risk_count: number;
  };
};
```

摘要本來就是 LLM 產的，讓它多吐幾個欄位比前端從一段文字裡剖析可靠得多。**建議做**，但不阻塞這一批。

## 危急通知詳情：已決議開例外

**危急事件開逐字例外**——家屬要判斷該不該打電話，只給一句摘要不夠。規格見 `handoff/危急通知詳情-後端規格.md`。

三樣東西後端都還沒有：`AppNotification` 連 id 都沒有（無法從清單導到詳情）、沒有錄音端點、沒有送達狀態。

**開例外有一件不能省的事**：現行同意條款沒有提到「家屬可在危急事件時看到逐字與錄音」。這是實質變更，**需要重新取得同意**，不能靜默上線。條款草稿還沒寫。
