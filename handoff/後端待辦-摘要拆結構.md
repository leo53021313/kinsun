# 後端待辦 · 每日摘要拆結構

**現況**：`DailySummary = { date, content, created_at }` — 一段純文字。

**要做**：讓產摘要的 LLM 多吐幾個欄位。摘要本來就是 LLM 產的，讓它結構化輸出比前端從一段文字裡剖析可靠得多。

---

## 型別

```ts
export type DailySummary = {
  date: string;
  content: string;          // 保留，向下相容；舊版 App 仍讀這個
  created_at: number;
  // --- 以下新增，全部 optional，前端有 fallback ---
  /** 長輩的原話，照登不改寫。3–5 句。 */
  quotes?: string[];
  /** 阿白注意到的關聯。明說不是診斷。1–3 句。 */
  observations?: string[];
  stats?: {
    medication_confirmed: number;
    medication_total: number;
    /** 自然語言，不是分數：「還不錯」「比較安靜」 */
    mood: string;
    turns: number;
    risk_count: number;
  };
};
```

全部 optional 是刻意的——後端分批上線時前端不會壞。

---

## 產生規則

**`quotes` 照登，不改寫、不美化。** 家屬要的是「阿公自己說了什麼」，不是 LLM 的轉述。挑選標準：提到身體、家人、情緒的句子優先；寒暄不收。

**`observations` 是關聯，不是診斷。** 可以說「第三次提到睡前藥會想睡」，不可以說「疑似藥物副作用」。每一句都要能追溯到當天的對話，不能引用長期記憶做推論——那會讓家屬以為是新發現的事。

**`stats.mood` 用自然語言。** 不要 1–5 分。家屬要拿這頁跟醫師講話，「還不錯」比「3.5 分」有用。
