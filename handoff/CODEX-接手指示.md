## 二、不可違反的規則

這些是設計決議，不是偏好。動到就要先問。

**長輩端**
1. 文字下限 **22px**，不設放大上限。
2. 每個畫面**一屏內不捲動**——長輩不一定知道要滑。唯一例外：系統字級 ≥150% 時只有內容層可捲，角色、頁首、主鍵仍固定。
3. 角色舞台 **209 × 300 固定在 top 140，永不縮放或位移**。需要空間時讓位的是麥克風主鍵（132 → 72）與回話卡。
4. 觸控目標 ≥ 48dp；長輩端主鍵 132dp。
5. **不出現「通知」二字**（叫「阿白的提醒」），QR 叫「方塊圖」。
6. 狀態一律**顏色＋圖示＋文字**三重編碼。

**角色與人稱**
7. 角色叫**阿白**（北極熊），自述用**第一人稱「我」**。
8. **「金孫」是服務名**，品牌字樣、App 名稱、同意條款主體保留不改。**不可以全域取代。**
9. 兩層情緒：系統態（5 個）驅動光暈與狀態帶；回應情緒（45 個）**只換角色本身**，不得改光暈或狀態文字。
10. 情緒黑名單寫死在程式裡：`angry / furious / annoyed / disgusted / jealous / suspicious / bored / sulking / panic / shocked / scared`。**必須擋在 `sentiment.js` 的本地關鍵詞比對之後**，不能只擋 LLM。

**不要動**
11. `talkGesture.ts` / `talkSocket.ts` / `talkPresentation.ts` 三支狀態機都有測試，這次只換呈現層。五個視覺狀態的名稱與時機完全沿用。
12. **分段播放的延遲優化要保留**——伺服器只先合成第一句就送出。回話卡的展開要接**第一段抵達**，不是整段合成完。這是為了讓長輩不用等 5–8 秒。
13. 觀測後台（`admin.css`）不套這套色，維持冷灰。它是內部工具不是品牌延伸。

**色彩**
14. 暖黃 `#F9DF77` 是**每頁唯一主要行動**，配深靛藍字 `#25285F`，不配白字。
15. 紅色 `#D95D5D` 只用於邊界與圖示；紅色文字用 `#B33C3C`，白字徽章底用 `#C64848`。
16. 次要文字用 `#6B6D88`（舊的 `#73758F` 在暖米白底只有 4.03，不合格）。

## 三、施工順序

照批次做，每批可獨立驗收。批次說明檔裡有各自的驗收清單。

1. **換 token 與文案** — 覆蓋 `theme.ts`、`strings.ts`；改 LLM system prompt 與 `sentiment.js` 的過濾點
2. **共用元件** — 覆蓋 `ui.tsx`
3. **對講機呈現層** — `talk.tsx` 四處改動＋接上 `BearStage`
4. **之前聊過的** — 新畫面＋`todayLog`，不用動後端
5. **家屬端路由重整** — Stack 改 Tabs，**最容易出錯，單獨做單獨驗**
6. **家屬端新畫面** — 摘要、改回診、危急詳情

批次 1 刪掉 `talkColors` 會讓引用它的檔案編譯失敗。**這是刻意的**，順著錯誤清單改比自己找漏網可靠。

## 四、已知的坑

**批次 3**
- `talk.tsx` 有 799 行，含錄音與分段播放的競態處理。**不要整份重寫**，照說明改那四處。
- `collapsed` 是新旗標，不是新的 `TalkVisualState`。狀態機測試要維持全過。
- RN 沒有 radial-gradient。光暈目前用大圓角色塊近似，要更接近設計稿得換 `expo-linear-gradient` 或出漸層 PNG。

**批次 5**
- expo-router 是檔案路由。`guardian/_layout.tsx` 一放進去，底下**所有**檔案都變成 tab。深層頁要先搬到 `guardian-detail/`，登入註冊搬到 `auth/`。
- Android 實體返回鍵在 tab 內預設會退出 App，要 `BackHandler` 處理。
- 深層頁返回全部用 `push`，用 `replace` 會斷掉返回原 tab 的行為。
- 未讀數要由 `notifications.tsx` 自己 `setOptions`，layout 拿不到 session。

**批次 6**
- 開關用 `Button` 的 primary/subtle 兩態代替。RN 原生 `Switch` 套不上這套視覺。
- `guardian-alert-detail.tsx` 的 API 呼叫是 TODO，後端端點還不存在。

## 五、還缺的東西（不是你的工作，但會擋到你）

**素材** — `assets/images/bear/` 需要五張系統態（684 × 980 直式透明 PNG，四邊留 8% 透明邊）＋常用情緒。**目前沒有**，批次 3 只能先用暫用圖跑通結構。`speaking` 那一態要**可對嘴的向量版**而不是靜幀。

**後端三件**
- 危急詳情三個端點（規格已寫）
- `AppNotification` 加 `notification_id` 與 `risk_event_id`（現在連 id 都沒有，無法從清單導到詳情）
- 摘要拆結構（規格已寫，非阻塞）

**條款** — 危急逐字例外需要重新取得同意，草稿已寫但**要法務審過**。未重新同意的帳號，危急詳情頁降級成只顯示原因與時間。

## 六、順帶一提

`TurnReply.duration_ms` 的註解寫著「保留給虛擬形象動畫對嘴（階段 5 後）」——這欄位早就為對嘴留好了，Otto 的注音 viseme 可以直接用，不用另外要後端加。

## 七、工作方式

- 每個批次做完就停下來讓人驗收，不要一口氣做完六批。
- 遇到設計稿與程式現況衝突時**先問**，不要自己決定——設計稿是給人看的提案，程式是實作依據，兩者不一致通常代表有東西沒對齊。
- 型別不確定時去讀 `RAG/shared/types.ts`，不要照畫面需求推測欄位。（先前就發生過：摘要畫面推了七個不存在的欄位。）
