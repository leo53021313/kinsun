## 2. 商業目標

### 2.1 背景與痛點

- 台灣 65 歲以上一人戶占比 25.8%（內政部，2025）；逾五成中高齡者感到寂寞；台北市逾四成「孤獨死」長者三天後才被發現（提案引用數據）。
- 雙邊痛點：**長輩**——打字難、白天沒人說話、身體情緒說不出口；**家屬**——不在身邊、只能偶爾打電話、出事太晚知道。
- 差異化核心：**同一段對話，一路陪聊、一路守護**——陪伴與照看用同一個互動完成。

### 2.2 策略契合度

- 期末發表（8/20）是就業媒合場合：產品完成度、工程品質（文件、測試、架構）都是展示物。
- 台語支援是提案明訂的「別組難抄」差異化——✅ D-01 維持列入範圍。

### 2.3 成功指標（⚠ D-05：類別已定，數值目標帶會議）

| 類別 | 指標 | 目標值 |
| :--- | :--- | :--- |
| 守護品質 | 危急偵測 precision／recall（標注測試集，漏報優先） | ⚠ 會議定 |
| 體驗 | 語音往返延遲 P50／P95（App 對講機實測） | ⚠ 會議定（提案原目標 3–4 秒） |
| 差異化 | 台語 ASR 錯誤率；台語 TTS 微調前後對比（CosyVoice 3 vs VoxCPM2） | ⚠ 會議定 |
| 易用性 | 長輩實測任務完成率＋滿意度問卷 | ⚠ 會議定（提案原定 7 位長輩） |

> as-is 缺口：程式碼目前**無任何 KPI 量測基建**（LLM token 用量記 NULL `src/kinsun/pipeline.py:146-160`、無延遲統計匯出）——列入差距總表 G-6。

## 4. 範圍與限制

### 4.1 功能範圍（in scope）

語音對話（國語＋台語 D-01）、文字對話（D-11 新增）、危急偵測分級與家屬通知、用藥／回診提醒、主動關懷、家屬 App（帳號／綁定／健康報告）、App 內通知（D-12 新增）、衛教 RAG（D-03）、開發觀測後台（admin）、LINE 通道（凍結維運，不加新功能，D-08）。

### 4.2 非功能需求

| 面向 | 需求 |
| :--- | :--- |
| 性能 | 語音往返延遲 ⚠ D-05（提案原 3–4 秒）；DGX 單機承載期末展示規模 |
| 安全 | 知情同意閘門必開（正式環境禁 AllowAllGate）；同意文案明示資料去向與永久保留（✅ D-14、D-15）；細部安全項於 13_安全與就緒檢查 |
| 可用性 | 部署單元：FastAPI 後端＋排程 worker＋DGX ASR/TTS；具體 SLO 於 14_部署與運維 |

### 4.3 不做什麼（out of scope）

- 穿戴裝置整合（HealthKit／Health Connect／Apple Watch）——✅ D-02 正式移除。
- 醫療診斷、開藥、調藥建議（RAG 安全閘門主動攔截）。
- 沿用提案排除項（若要翻案請於會議提出）：真人臉動畫／即時嘴型、國台語同句混合辨識、大型多長輩機構後台、自研對話模型（用 Gemini）。

### 4.4 假設與依賴

- 假設：家屬有智慧型手機並能安裝 Expo Go／App；長輩裝置由家屬代設（定位 ⚠ D-06）。
- 依賴：Google Gemini API（LLM＋embedding）、Supabase（Postgres＋pgvector＋Storage）、Mem0、DGX Spark（ASR：Breeze-ASR-26／TTS：CosyVoice 3）、Expo（無 Mac 環境靠 Expo Go 實機預覽）、LINE 平台（凍結通道維運）。
- 對外傳輸：長輩對話經第三方雲端 AI 處理——同意文案須明示（✅ D-15）。
