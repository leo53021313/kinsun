## D. 基礎設施安全

- [x] Secrets：無金鑰入庫、.env 未追蹤、.example 無真值 ✅
- [x] lock 檔：uv.lock＋三個 package-lock（frontend／app／web）✅；**DGX requirements 未鎖 ❌** → ✅ D-56
- [x] 依賴掃描：✅ CI audit job（戊-1，2026-07-10）——`pip audit`＋frontend／app／web `npm audit --audit-level=high`（警示不擋門，`continue-on-error: true`）
  - **2026-08-09 清理**：`pip-audit` 自 2026-08-08 起紅字（7 個新揭露的 CVE）。升 `aiohttp` 3.14.1→3.14.3、`cryptography` 49.0.0→50.0.0、`h2` 4.3.0→4.4.1、`pypdf` 6.14.2→6.15.0（後者為直接依賴，`pyproject.toml` 下限一併抬到 6.15.0，只鎖 lock 擋不住重新解析時掉回舊版）。實測 `uv export`＋`pip-audit` 已為 `No known vulnerabilities found`。`frontend`／`web` 以 `npm audit fix` 清零（皆為建置鏈傳遞依賴：brace-expansion／js-yaml／nanoid／undici），兩者建置與測試全數通過。
  - ⚠️ **`app` 的 12 個 high 刻意不修**（Leo 裁決，2026-08-09；2026-08-10 重跑另列出 14 個 moderate）：`npm audit` 給 high 的唯一修法是把 `expo` 54→**46**、`react-native` 0.79→**0.72**，等於把 App 倒退兩年。這些套件（`metro`／`@expo/cli`／`@testing-library/react-native`／`image-size`）只在建置與測試時用到，不會打包進長輩手機裡的 App；且 App 已於 2026-07-30 凍結、改由 `web/` 當唯一前端。**代價已知並接受**：audit job 會持續紅字，且排在 `app` 之後的 `web` 那步在 CI 上永遠不會執行（本機已代為驗證）。日後真有該處理的新漏洞時，這片紅字會蓋住它——要恢復訊號，必須先處置這 12 個 high；14 個 moderate 尚未納入本次 high 門檻裁決。
- [x] 告警：被動 admin 橫幅兩則（✅ 庚-55 更正）——分級器故障（D-31 甲-5）＋家屬通知送失敗（庚-02）；主動推送管道仍無（接受，維運開後台）
