| 維度 | 目標 | 備註 |

- 回覆音檔隨 WS binary 訊框直送（2026-07-30 延遲優化 C1）：`lib/replyAudio.ts` 把位元組寫成`Paths.cache/kinsun-reply/*.m4a` 再交給播放器，省掉「後端上傳 Supabase→App 再下載」兩趟網路。三個實作約束：①`expo-audio` 的 `AudioSource` **只吃 uri**，沒有吃記憶體位元組的路（iOS 雖認得 `data:audio/…`，但它內部就是寫進拿不到檔名、永不清理的暫存目錄，副檔名還靠 MIME 猜）；②副檔名**必須**是 `.m4a`，AVPlayer 推不出型別就載不起來；③`expo-file-system` v54 的舊 API（`writeAsStringAsync` 等）**執行期會拋**，只能用 class-based 的 `File`／`Directory`／`Paths`，而 `File.write` 吃 `Uint8Array`、是同步呼叫（回傳即已落盤，故 write→replace→play 無競態）。

- web 端：內部工具，不做 code splitting 投資；admin 輪詢 5s＋隱藏暫停＋回前景補跑（✅ D-47 維持）。

  - **權限請求的時機是架構約束，不是實作細節**（Critical 2）：`elder/location.ts::currentPlace` 的回傳值 100% 被丟棄（F-17），卻仍在 `startRecording` 之後呼叫 `getCurrentPosition`——權限對話框會在**錄音進行中**彈出，與 2026-07-18 App 端「iPhone 錄音全數 ≤0.72 秒」是同一個坑（見 17）。⚠️ **凡是會跳系統權限對話框的呼叫，一律在進畫面時完成，不可以掛在長輩按住麥克風的那條路徑上**；`useTalk` 的 `probeMicrophone` 已是這個形狀，取位恢復（F-17）時必須跟進。
  - **「這一欄看不看得見」要以斷點為準，不是以頁籤狀態為準**（Important 2）：`StagePage` 的 `elderVisible` 原為 `pane === "elder"`，而頁籤是 `lg:hidden`；寬窄本身會在使用中改變（縮放視窗、Ctrl+ 放大字級——Tailwind 的 `lg` 是 CSS px），於是會出現「兩欄同時可見、`pane` 卻停在 `"guardian"`」的狀態：長輩欄看起來完全正常（cleanup 重設了字幕）但麥克風永遠打不開，而 `lg` 以上沒有任何 UI 撥得回來。改用 `matchMedia("(min-width: 1024px)")` 訂閱同一個斷點（`isWide || pane === "elder"`）。⚠️ 斷點數字與版面的 `lg:` 前綴是同一件事的兩種寫法，改一邊就要改另一邊；jsdom 沒有 `matchMedia`，取不到一律當「不是寬螢幕」＝頁籤模式語意。
  - **降級路徑不可以把後端寫好的人話換成自己的通用句**（Important 1）：`POST /turns` 的 503／429／413 都帶著繁中 message，前端一律收斂成「金孫沒聽清楚，再說一次好嗎？」會讓長輩更大聲再講一次、再打一輪進已經滿載的閘門。改接 `api.ts::apiErrorMessage`（與 `elder/LoginScreen.tsx` 同一支）：後端真的解出信封的照顯示，`shared/client.ts` 自造的 `http_<status>` 英文訊息退回 fallback。
