## 1. 執行單元與啟停

`scripts/kinsun.sh` 統一管理八服務：`asr(8001) tts(8002) webhook(8000) scheduler rag_worker frontend(5173) app(8081) ngrok`——setsid 獨立進程組、log 至 `logs/<name>.log`、PID 至 `.run/<name>.pid`。

| 指令 | 行為 |
| :--- | :--- |
| `scripts/kinsun.sh start|stop|restart [服務]` | 全部或指定服務（如 `restart app`） |
| `scripts/kinsun.sh status` | PID 存活檢查；`app` 那列即 Expo Go 要掃的 `exp://` 位址 |

**App（Expo dev server）**：**預設走 tunnel**（✅ 團隊測試手機與 DGX 從不在同一個 Wi-Fi）——Expo 經 `exp.direct` 反向隧道對外，任何網路的手機都連得到，`status` 顯示形如 `exp://xxx-anonymous-8081.exp.direct` 的對外位址供 Expo Go 掃描（iOS 用相機、Android 用 Expo Go 內建掃碼）。

- **位址從哪來**：Expo 只在互動終端印 QR／網址，背景啟動時 log 裡一個字都沒有——`status` 改問 Metro 的 manifest（`launchAsset.url` 的 host 即手機實際要連的位置），tunnel 與 LAN 兩種模式都準。
- **tunnel 偶發失敗**：`exp.direct` 端會出現 `remote gone away`，且失敗時 Expo 整個退出、連 Metro 都不留。故啟動時會等到 tunnel 就緒才算數，**失敗自動重試一次**（實測命中率頗高）。兩次都失敗時另有明確提示。
- **區網模式**：`KINSUN_EXPO_TUNNEL=0`（僅同網段可用、啟動較快）。此模式以 `REACT_NATIVE_PACKAGER_HOSTNAME` 釘住區網 IP——DGX 有 docker(172.17.x)／Tailscale(100.x) 等多張網卡，不釘住則 Expo 可能挑錯介面、手機抓不到 bundle。

to-be：API 改多 worker 啟動（✅ D-20）。

## 3.5 資料庫連線總量（✅ 庚-26／A-55）

Supabase 直連（5432）上限＝免費方案約 60 條。每進程開一個連線池，
上限 `DATABASE_POOL_MAX_SIZE`（預設 5）。總量公式：

```
（WEB_WORKERS ＋ scheduler 1 ＋ rag_worker 1）× DATABASE_POOL_MAX_SIZE ≤ 60
```

- 預設（WEB_WORKERS=2）常駐 20 條，寬裕；**WEB_WORKERS 安全上限約 7**（45 條，留 CLI 餘裕）。
- 零星加項：記憶整理 CLI、RAG ingest、備份腳本各短暫 +5。
- ⚠️ 不可為了拉高上限改用 6543 交易池化埠：認證節流（庚-08）依賴 advisory lock，
  交易池化下 session 級鎖語意不成立。
- 爆線症狀＝連線被拒（API 500），不是變慢——排障時先想到本公式。

### RAG 週更 Runbook

- `RAG_REFRESH_ENABLED=true` 且 `RAG_REFRESH_CRON=0 3 * * 0` 時，`rag_worker` 每週日 03:00 建候選版。
- `rag_worker` 使用專用最小設定，只需要 `DATABASE_URL`、`DATABASE_POOL_MAX_SIZE`、`GEMINI_API_KEY`、`TIMEZONE`、`SCHEDULER_TICK_SECONDS` 與 RAG 設定；不應因 LINE、LIFF、ASR、TTS 或音檔設定缺漏而無法啟動。
- `RAG_EMBEDDING_TIMEOUT_SECONDS=60` 限制單次外部呼叫；`RAG_EMBEDDING_BATCH_SIZE=20` 限制同步批次，避免巨型頁面造成無限等待。ANSWER 才建立向量，DISCOVERY 只留文件 membership 與稽核。
- `scripts/kinsun.sh status` 確認 `rag_worker` 存活；失敗原因看 `logs/rag_worker.log` 與 Admin「衛教 RAG 索引」。
- 無 active release 或最近更新失敗時 Admin 會告警；舊 active 仍服務，不得直接改 DB status。
- 外部額度或 timeout 造成 failed release 時，重跑會復用其中已原子完成、同模型／維度／角色且結構合格的文件；不可手動把 failed 改 active。
- 每分鐘節流與每日配額是不同限制；提高 `RAG_EMBEDDING_DELAY_SECONDS` 只能處理前者。額度用盡時等待重設或提高方案後再建版，release 必須維持 failed。
- 2026-07-18 個人庫已成功發布 `rag-20260718T055933Z`（790 文件／2,808 chunks，threshold 0.65，recall 100%、false-positive 0%、安全 100%、citation correctness 90%）；`RAG_REFRESH_ENABLED` 已於驗收後啟用。
- 人工立即跑：`PYTHONPATH=src uv run python -m kinsun.rag.worker --once`。
- 回滾：先 `PYTHONPATH=src uv run python -m kinsun.rag.release_cli list`，再 `PYTHONPATH=src uv run python -m kinsun.rag.release_cli rollback <index_version>`。
- `classroom_demo` 僅限課堂；公開部署前必須改回 `allowed_only` 並重新建版。

## 工程觀測（Opik）服務

工程／LLM 深度視角的觀測後端，自架於 DGX，**不進版控**（外部基礎設施，比照資料庫）。

- **服務位置**：`/home/leo29/opik`（git clone，非 kinsun repo）；容器名 `opik-opik-*`。
- **啟停**：`cd /home/leo29/opik && ./opik.sh`（啟動）／`./opik.sh --stop`／`./opik.sh --clean`（清資料）。也可經 kinsun.sh 一併管理（見下「遠端檢視」——`opik` 服務會連後端 docker 一起起停）。
- **連結顯示**：`scripts/kinsun.sh status`／`start` 結尾會印出 Opik 觀測後台連結（由 `OPIK_URL_OVERRIDE` 去 `/api` 推得，預設 `http://localhost:5273`）、服務是否在跑、以及 `OPIK_ENABLED` 旗標。
- **kinsun.sh 管理（服務名 `opik`＝後端 docker ＋ 公開隧道，複合服務）**：已納入 `START_ORDER`／`STOP_ORDER`，隨 `start`／`stop`／`restart`（全部）一起起停；亦可單獨 `start/stop/restart opik`。
  - `start opik`：先確保**後端 docker**（`./opik.sh`）起來（冷啟等 5273 健康，約 30–60 秒），再開 Cloudflare Quick Tunnel（cloudflared，已裝於 DGX，aarch64）。
  - `stop opik`：先關隧道（pidfile），再由 `_post_stop_opik` 停後端 docker（`./opik.sh --stop`）。後端非單一 PID，故特別處理（`is_running(opik)`＝後端 :5273 是否在；隧道另用 pidfile 判斷）。
  - `status`：`opik` 那列 STATE＝後端狀態，PORT/HEALTH 欄顯示「後端 :5273 | 隧道 <當前 `*.trycloudflare.com` 網址>」（網址每次重啟會變，讀 `logs/opik.log` 最後一次啟動後的區段）；另有一行本機後台連結＋`OPIK_ENABLED` 旗標。
  - ⚠️ **Quick Tunnel 限制**：網址每次重啟都不同；且短時間反覆建立會被 Cloudflare 匿名隧道**限流**（新子網域暫時無法解析／不可達）——heavy start/stop churn 後稍等再試即可，這是 Cloudflare 端行為、非本專案缺陷。要固定網址＋認證＋不被限流，需正式版 Named Tunnel＋Access（待有 CF 網域）。
  - ⚠️ **安全**：Quick Tunnel 免網域但【公開、無認證】——Opik 自架版本身無登入，等於任何拿到網址者可讀所有 trace。**注意 `OPIK_ENABLED` 現預設為 `true`**（連得到 Opik 就送 trace），故真實對話內容預設會進 Opik；**接真實長輩資料時，切勿開啟公開隧道**（要遠端檢視改用下方 Named Tunnel＋Access）。純 demo/測試資料臨時開無妨。
  - **正式版（有 Cloudflare 網域時）**：改用 Named Tunnel＋Cloudflare Access（Email/Google 登入），提供固定子網域＋認證。需 `cloudflared tunnel login`（互動授權本人 CF 帳號）後建 tunnel／DNS／Access 政策。目前無網域，故先用 Quick Tunnel。
  - ngrok（webhook :8000）留給 App API（見 §1；`app/.env` 的 `EXPO_PUBLIC_API_URL` 指向該網域），不與 Opik 隧道互搶；免費 ngrok 只有一個網域，故 Opik 不共用 ngrok。
- **對外埠**：僅前端 `5273`（UI＋API 反代）；資料庫（clickhouse/mysql/minio/redis/zookeeper）預設不對外，與 kinsun（postgres 5433／uvicorn 8000）零衝突。
- **資料本體**：docker named volumes（rootless：`~/.local/share/docker/volumes/opik-opik_*`）；**要備份的是這些 volume**，服務程式碼可重新 clone。
- **ARM64**：核心映像原生 aarch64（已驗證）；選配 Guardrails（PII/主題，英文模型、吃 GPU）預設關閉且無 arm64 映像，需用再自 build。

### 環境變數（OPIK_ 前綴；app 端 client）

| 變數 | 預設 | 說明 |
| :--- | :--- | :--- |
| `OPIK_ENABLED` | `true` | 總開關；預設開送 trace，連不到 Opik 服務會安靜降級為 no-op（見 `OPIK_PING_TIMEOUT_SECONDS`）。開發機不想跑 Opik 設 `false` 明確關 |
| `OPIK_URL_OVERRIDE` | `http://localhost:5273/api` | 自架 Opik 後端位址（搬遷只改此值） |
| `OPIK_WORKSPACE` | `default` | 自架工作區 |
| `OPIK_PROJECT_NAME` | `kinsun` | Opik UI 內的分組 |
| `OPIK_PING_TIMEOUT_SECONDS` | `2.0` | 啟用時的連線探測逾時；`configure()` 在此秒數內判定 Opik 是否可達，連不到即降級 no-op，避免無服務環境（開發機／CI）被連線錯誤洗版 |

> **安全**：接真實長輩資料時，Opik 自架版預設幾無存取控制；共用或上線前須先處理存取控制與去識別化。
