## 2. 高風險契約 DbC

### 2.1 `RiskDetector.assess(text) -> RiskAssessment`（safety/detector.py:16）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | text 為 ASR 轉寫或長輩文字（D-11 後含打字），可為空字串 |
| 後置 | 回 RiskTier＋信心＋signals；**絕不拋例外、絕不中斷對話**。三級 L0／L1／L2（✅ D-72，己-4 已落地；舊資料 tier=3 讀取時夾回 L2） |
| 不變量 | 絕對危急詞命中→直上頂級 L2（不受門檻）；`final=max(關鍵詞,LLM)`；降級規則（✅ 己-4 重設計）：純 LLM 判 L2 且信心<mid 降 L1，單一門檻；`SAFETY_CONFIDENCE_HIGH` 已隨 L3 移除，僅剩 MID（0.4，實測再調——會-7） |
| to-be（✅ D-31） | LLM 失敗：現況靜默 L0 → 失敗率超門檻觸發維運告警；該句非空保守記 L1 留痕（需新增 L1 落庫路徑，落庫門檻由 `tier≥L2` 改為含 fail-safe L1） |

測試案例錨點：`test_safety_detector`（雙軌合併、降級規則）；to-be 需補：分級器連續失敗→告警觸發；失敗句→L1 事件存在且不通知。

### 2.2 `ConsentGate.resolve_elder(channel, external_id) -> elder_id | None`（binding/gate.py:22）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | (channel, external_id) 為任意通道帳號，可能未綁定 |
| 後置 | 僅當綁定存在**且** `has_valid_consent` 才回 elder_id；否則 None |
| 不變量 | 查詢故障一律回 None（**不 fail-open**）；token 有效≠同意有效（App turns 每回合複核） |
| to-be（✅ D-19） | `AllowAllGate`（開發旁路）也解析為 elder_id，統一會話鍵語意 |

### 2.3 `VoicePipeline.process(audio, *, elder_id, ...) -> TtsResult`（pipeline.py:47）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | elder_id 已過閘門解析；audio 為有效音檔 bytes（上限 env 化 ✅ D-26） |
| 後置 | 回文字＋（可能的）語音；五階段 trace 落庫（safe_record 失敗不影響對話） |
| 不變量 | tier≥L2 時**先**落庫＋通知**再**生成回覆（回覆失敗不影響通知）；落庫失敗仍通知；TTS 失敗退純文字 |
| to-be | 通知送達與否獨立記錄（✅ D-36）；token 用量落庫（G-6）；文字輸入走同管線（✅ D-11，`process_text` 由 Debug 轉正式） |

### 2.4 `SessionMemory.assemble(elder_id, query) -> TurnContext`（memory/recall.py:38）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | elder_id 為業務主鍵（非通道 ID） |
| 後置 | 三層合成：長期記憶（user query＋固定健康查詢）＋事實段（用藥／回診）＋今日對話 |
| 不變量 | 長期檢索故障→無記憶繼續；單一事實提供者失敗→略過該段；今日視窗上限＝max_turns（統一 200 ✅ D-35） |
| to-be（✅ D-40） | search 開 explain（評分明細）＋reranker（provider 實作時比較後快速確認）；中文實體辨識列調查 |

### 2.5 `AccountService.redeem_invite(code, ...) -> Elder`（accounts/service.py:117）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | code 為 16+ 字元邀請碼字串 |
| 後置 | 綁定通道帳號＋寫同意（SELF／PROXY）＋（首綁）記 escalation_order |
| 不變量 | not_found／used／expired／too_many_attempts 四態互斥；嘗試計數單調遞增；同意版本 CONSENT_VERSION |
| to-be | 家屬 token 效期＋登出、長輩裝置可作廢重綁（✅ D-25） |

### 2.6 `Scheduler.run_due(now)`（scheduler/scheduler.py:35）

| 類型 | 條件 |
| :--- | :--- |
| 前置 | jobs 具唯一 name＋合法 cron |
| 後置 | 到期 job 各執行至多一次；last_run 持久化（upsert） |
| 不變量 | 首見只種基準不觸發；錯過只補一次；單 job 例外不影響其他 |

## 3. 測試策略現況

- **總量**：1247 tests collected；118 個 Python 測試檔（2026-07-17 重掃）；另有 JS 測試 4 檔（frontend vitest×3＋app jest-expo×1，2026-07-17 起與 CI frontend／app job 綁定）。

- **整合測試**：`KINSUN_IT=1` 啟用 Pg 分支＋`test_pg_db`＋`test_pg_observability_store`。
- **規範**：TDD、80% 覆蓋率門檻（.claude/rules/testing.md）——✅ 2026-07-10 起 CI 以 `pytest --cov=kinsun --cov-fail-under=80` 把關（現況 87%）。
