# ADR-002: 資料庫與儲存採 Supabase（Postgres＋pgvector＋Storage）

> **狀態:** 已接受 | **日期:** 2026-07-08 | **決策者:** Leo（批次重新確認）

## 1. 背景與問題

- **上下文**: 需要關聯式資料庫（22 表）、向量檢索（Mem0＋RAG）、音檔託管三種儲存。
- **問題**: 自架三套服務對 7 人學生團隊維運成本過高。
- **驅動因素/約束**: 免費層額度；DGX 在校內、雲端 DB 可從任何開發機連。

## 2. 考量的選項

- **Supabase**：託管 Postgres＋pgvector＋Storage 一站式，免費層夠用。
- **自架 Postgres（DGX）**：零月費但要自己備份、對外連線要打洞。
- **RDS／Cloud SQL**：超出預算。

## 3. 決策

**選擇**: Supabase 一站式（`DATABASE_URL`＋Storage bucket）。

**理由**: 一個服務覆蓋三種需求；pgvector 讓 Mem0 與 RAG 共用同一庫。

## 4. 後果

- **正面**: 零維運；向量與關聯資料同庫、可 join。
- **負面**: 長輩資料存第三方雲端（→ D-15 同意文案明示）；⚠ 音檔目前放**公開 bucket**（知 URL 即可存取），安全疑慮於 13_安全循環議決。
- **重新評估觸發**: 免費層額度不足；個資合規要求資料落地時。
