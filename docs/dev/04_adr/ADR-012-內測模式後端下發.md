# ADR-012: 內測模式後端單一開關（INTERNAL_TESTING_ENABLED 經公開 meta 下發）

> **狀態:** 已接受 | **日期:** 2026-07-12 | **決策者:** Leo（內測基礎建設 spec，已實作合入 main，PR #45）

## 1. 背景與問題

- **上下文**: 內部測試需要兩個「不得流入正式版」的能力——App 一機雙端快速切換、觀測後台手動觸發排程與提醒（D-73）。
- **問題**: 這些能力的開關放哪裡？內測裝置含自建 APK（環境變數 build 時即固定、裝完改不了），且開關要能一鍵切換、正式環境保證關閉。

## 2. 考量的選項

- **後端單一開關＋API 下發**：後端 `.env` 一鍵 `INTERNAL_TESTING_ENABLED`，公開 `GET /api/v1/meta` 回 `{internal_testing: bool}`；App 與 admin 前端啟動時查一次，取不到一律當 false。
- **前後端各一個開關**：後端管後台按鈕、App 用 `EXPO_PUBLIC_*` 管切換器——兩處要同步，且 APK 想關閉切換器得重新 build 發版。
- **不設總開關**：每個內測功能各自旗標——開關仍多把，沒有解決「統一」的痛點。

## 3. 決策

**選擇**: 後端單一開關＋公開 meta 下發（spec 2026-07-12 §3.1，批①～③已實作）。

**理由**: 一個鍵管全部（App 切換器＋後台觸發按鈕與 API）；開關在伺服器端，APK 免重發版；前端 fail-safe（meta 取不到＝正式行為）。觸發類 API 另以 admin key＋本開關**雙重守門**（403 `internal_testing_disabled`），公開 meta 僅洩漏一個布林、無機敏值。

## 4. 後果

- **正面**: 內測／正式切換＝改一鍵重啟；後續內測專用功能一律掛同一開關（環境變數前綴 `INTERNAL_TESTING_`，命名決策 #37）。
- **負面**: App 啟動多一次輕量 API 呼叫；「伺服器開著內測模式」對外可探知（僅布林，接受）。
- **重新評估觸發**: 內測功能需要「按裝置／按帳號」細粒度開關時（目前全域一鍵已足夠）。
