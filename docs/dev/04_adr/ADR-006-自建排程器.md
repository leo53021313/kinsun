# ADR-006: 排程採自建 Scheduler（croniter＋Postgres 持久化）

> **狀態:** 已接受 | **日期:** 2026-07-08 | **決策者:** Leo（批次重新確認）

## 1. 背景與問題

- **上下文**: 12+ 個每日定時任務（用藥×4、回診、問候、失聯、記憶整理、清理）需可靠觸發。
- **問題**: 需要「錯過補跑一次」語意與跨進程互斥，避免重複提醒。

## 2. 考量的選項

- **自建**（croniter 算下次觸發＋`scheduler_state` 表存 last_run＋advisory lock）
- **APScheduler**：功能夠但持久化後端與補跑語意要客製。
- **Celery beat**：需另架 broker（Redis），維運成本不合理。

## 3. 決策

**選擇**: 自建 `Scheduler`（`src/kinsun/scheduler/scheduler.py:24`），獨立 worker 進程跑，tick 60 秒。

**理由**: 需求面窄（每日 cron＋補跑），自建 200 行內解決；已實作完整含 fanout 失敗隔離。

## 4. 後果

- **正面**: 零額外基礎設施；行為完全可控可測。
- **負面**: 自建代碼自己維護；不支援秒級／高頻排程（目前無此需求）。
- **重新評估觸發**: 需要分散式多 worker 或事件驅動排程時。
