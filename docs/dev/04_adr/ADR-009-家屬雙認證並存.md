# ADR-009: 家屬 REST API 雙認證並存（App token＋LIFF idToken）

> **狀態:** 已接受 | **日期:** 2026-07-08 | **決策者:** Leo（批次重新確認）

## 1. 背景與問題

- **上下文**: 家屬功能（用藥／回診／健康報告）同時服務 LIFF（LINE 登入）與 App（email＋密碼）兩種使用者。
- **問題**: 兩通道使用者要存取同一份資料，過渡期不能強迫遷移。

## 2. 考量的選項

- **雙認證並存**：`GuardianAuth` 先查 App Bearer token，再退 LIFF idToken 驗證（`web/api.py:70-83`）。
- **擇一（僅 App）**：強迫既有 LINE 家屬立刻遷移，體驗差。

## 3. 決策

**選擇**: 雙認證並存，同一家屬實體經 `channel_bindings` 對映。

**理由**: 符合 LINE「降級凍結不刪」（D-08）的過渡策略；App token 優先反映主線。

## 4. 後果

- **正面**: 遷移零強迫；後端 handler 無感（依賴注入解析）。
- **負面**: 兩套憑證生命週期並行（token 效期／撤銷政策於 06/13 循環議，現況 token 永久有效是已知疑慮）。
- **重新評估觸發**: LINE 通道退場時收斂為單一認證。
