# ADR-011: 通道中立身分層（elder_id 業務主鍵＋channel_bindings）

> **狀態:** 已接受 | **日期:** 2026-07-07 | **決策者:** Leo（App 轉型 spec 階段 1，已實作併入 main）

## 1. 背景與問題

- **上下文**: 系統原生於 LINE，會話、記憶、觀測全以 `line_user_id` 為主鍵——與單一平台死綁。
- **問題**: App 轉型（D-08）需要同一長輩跨 LINE／App 共享身分、記憶與守護狀態。

## 2. 考量的選項

- **身分層中立化**：業務主鍵改 `elder_id`／`guardian_id`（uuid），通道帳號經 `channel_bindings (channel, external_id) → 本人` 對映。
- **App 使用者另建平行帳號**：同一長輩兩套記憶／危急紀錄，守護斷裂，不可接受。

## 3. 決策

**選擇**: 身分層中立化（App 轉型 spec 階段 1A–1D，PR #38–#39 已完成）：會話主鍵遷移至 `elder_id`、Elder/Guardian 拔除 `line_user_id` 欄位、出入站經 ChannelRouter fan-out。

**理由**: 一次遷移根治「加通道要改主鍵」問題；順帶根治一 LINE 帳號綁多長輩的舊缺陷。

## 4. 後果

- **正面**: 新通道（web／電話）只需新增 adapter＋bindings 列；記憶與守護跨通道連續。
- **負面**: 遷移期已付出（舊 Mem0 記憶 100% 孤兒經實測確認為測試資料，未遷移）。
- **重新評估觸發**: 無——此為地基決策；變更需重走架構評估。
