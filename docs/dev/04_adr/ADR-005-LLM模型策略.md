# ADR-005: LLM 模型策略——開發期單一免費模型，上線前升級關鍵路徑

> **狀態:** 已接受 | **日期:** 2026-07-08 | **決策者:** Leo（D-16）

## 1. 背景與問題

- **上下文**: 對話回覆、**危急分級**、每日摘要、RAG 改寫全部使用同一顆 `gemini-3.1-flash-lite`（最低價位階）。
- **問題**: 危急分級是生死判準，與閒聊共用最便宜模型未經評估；但開發期免費額度（扣打）是硬約束。
- **驅動因素/約束**: 學生專案零預算；8/20 前呼叫量以開發測試為主。

## 2. 考量的選項

- **維持單一 flash-lite**：額度最省，分級品質風險由關鍵詞兜底。
- **立即分流（分級用較強模型）**：品質較穩但燒額度，開發期不划算。

## 3. 決策

**選擇**: **開發階段維持單一 `gemini-3.1-flash-lite`（免費額度多）；之後升級更高階模型負責重要路徑**（優先序：危急分級 > 對話回覆 > 摘要／RAG）。

**理由**: 開發期呼叫多、免費額度優先；架構上 `GeminiClient` 已集中封裝（`src/kinsun/llm.py`），屆時分流只需設定層支援多模型。

## 4. 後果

- **正面**: 開發期零成本；升級路徑明確。
- **負面**: 8/20 前的實測（含 KPI 的偵測 P/R 量測）反映的是 flash-lite 品質，升級後需重測。
- **影響範圍**: `config.py` 需支援按用途配模型（重構工項，餵 16_WBS）。
- **重新評估觸發**: 上線前；或偵測 recall 實測不達 KPI 時提前分流。
