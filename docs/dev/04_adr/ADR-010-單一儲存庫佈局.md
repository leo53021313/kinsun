# ADR-010: 單一儲存庫（monorepo）佈局

> **狀態:** 已接受 | **日期:** 2026-07-08 | **決策者:** Leo（批次重新確認）

## 1. 背景與問題

- **上下文**: 後端（src/kinsun）、App（app/）、web 前端（frontend/）、DGX 服務（services/）、測試（tests/）同倉。
- **驅動因素/約束**: 7 人「每人一分支＋整合負責人」協作模型（CONTRIBUTING.md）。

## 2. 考量的選項

- **monorepo**：跨層改動（如 API 欄位改名）一個 PR 完成，前後端契約同步。
- **多 repo**：邊界清楚但跨 repo 同步對新手團隊是災難。

## 3. 決策

**選擇**: 維持 monorepo。

**理由**: 前後端 snake_case 契約一致性（AGENTS.md 規範）靠同倉同 PR 最容易維持。

## 4. 後果

- **正面**: 單一 PR 流程；文件（docs/dev）與程式碼同倉演進。
- **負面**: repo 較大；`.gitignore` 型樣要小心（曾誤擋 app/src/lib）。
- **重新評估觸發**: services/ 需要獨立部署節奏或獨立團隊時。
