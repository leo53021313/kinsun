## 1. 設計原則

- **按領域組織**（package-per-domain 模組化單體）：`medications/`、`appointments/` 各自完整，不按類型分散——刻意偏離模板的 domains/application/infrastructure 三層目錄式，分層以 import 方向約束（見 [09_模組依賴關係](09_模組依賴關係.md)），對應關係見 [05 §1.3](05_架構與設計.md)。
- **組裝集中**：物件建構只發生在 `composition.py`／`app.py`／`scheduler/worker.py` 三個組裝根，handler 內禁止自行 new。
- **配置外部化**：一切設定走環境變數（`config.py`＋`.env.example`），程式不寫死金鑰。
- **src layout**：後端在 `src/kinsun/`，根目錄只放專案級檔案。

## 4. 新領域腳手架（實際慣例）

新增領域（例：`exercise/` 運動提醒）依需要裁剪六件套——**models／store／service 必備**，其餘按功能：

| 檔案 | 何時需要 | 範例依據 |
| :--- | :--- | :--- |
| `models.py` | 必備：frozen dataclass＋Enum | `medications/models.py` |
| `store.py` | 必備：三件套同檔（Protocol＋Pg＋Fake）；事件／狀態表可依語意命名（D-42 例外） | `medications/store.py` |
| `service.py` | 必備：建構子注入 store（＋依需要 new_id／clock，✅ 庚-53 對齊現實） | `appointments/service.py` |
| `facts.py` | 要注入對話上下文才加（實作 `FactProvider`） | `medications/facts.py` |
| `flow.py` | 有 LINE 引導選單才加 | `appointments/flow.py` |
| `jobs.py` | 有排程提醒才加（`build_*_job` 工廠，AGENTS.md 規範放領域內） | `medications/jobs.py` |

**接線三步**：`composition.py`（建 store＋service）→ 需要排程則 `scheduler/worker.py` 掛 job → 需要 API 則 `web/`（to-be `web/routers/`）掛 router。

## 5. 測試結構

- 平鋪於 `tests/`（不分 unit/integration 子目錄——整合測試以 `test_pg_*`＋`KINSUN_IT=1` 區隔）。
- 命名：`test_<套件>_<檔>.py`；合約測試 `test_<領域>_store_contract.py`（Fake 每次跑＋Pg 需 IT 旗標）。
- 缺套件前綴的 9 檔已改名完成（✅ D-44，丙-12 git mv）。
- JS 測試與被測檔同目錄（co-located）：frontend 用 vitest（`*.test.tsx`）、app 用 jest-expo（`*.test.ts`），各自 `npm test`，CI 併入 frontend／app job（2026-07-17）。
