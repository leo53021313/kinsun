## 1. Background（為什麼現在要做）

AIPE03 期末專案。台灣高齡照護場景中，長輩缺乏日常陪伴、家屬無法即時掌握異常；
長輩不擅打字，需要**語音優先**、**台語友善**的陪伴介面。LINE 是台灣長輩滲透率最高的通訊軟體，
以 LINE 官方帳號為載體可免安裝、免教學。

## 2. Problem Statement

1. 長輩：孤獨、沒有對話對象；忘記吃藥、錯過回診。
2. 家屬：不知道長輩今天好不好；有事（跌倒、胸痛、情緒低落）沒人通知。
3. 團隊（本專案特有）：程式碼看似完成，但**52 項產品決策未經人拍板**——目前最大的
   產品風險不是缺功能，而是**沒人決定過這些功能該長什麼樣**。

## 3. Goal / Non-goal

**Goal（MVP＝期末展示可驗收）**

- G1 長輩用 LINE 語音（國語）與金孫自然對話，回覆語音＋文字、有記憶。
- G2 長輩語音中的危急訊號被分級（L0–L3），L2 以上即時通知家屬。
- G3 家屬可建檔綁定、管理用藥／回診，到點提醒長輩。
- G4 家屬可查看長輩近 30 天健康報告。
- G5 開發團隊可在觀測後台看到每輪對話全鏈路。

**Non-goal（本階段明確不做）**

- 台語 ASR／TTS（後續換模型，契約不變）⚠ T-36 台語輸入的回覆策略仍須先議
- LINE 以外通道、電話語音
- 代理同意 PROXY、權限分級（`can_view_transcript` 等）落地 ⚠ T-20／T-26
- 危急通知 v2（升級鏈／ack／節流）⚠ T-07
- 衛教 RAG 上線（Jerry 分支獨立進行）⚠ T-50

## 4. Target User / Scenario

| 角色 | 情境 |
|------|------|
| 長輩（70+，慣國台語） | 早上收到金孫問候，按住麥克風回話；胸口不舒服時說出來，家人就會知道 |
| 家屬（子女，上班族） | 手機收到「長輩可能需要注意」推播；週末打開儀表板看近況、更新藥單 |
| 開發團隊 | 展示與除錯時全程開觀測後台，逐 trace 檢查延遲與錯誤 |

## 6. Acceptance Criteria（Given / When / Then）

> 完整逐功能驗收步驟與分工在 [功能實測驗收清單](../功能實測驗收清單.md)（A–E 區）；
> 以下為產品層驗收標準示例，QA 撰寫 Test Case 時以此為源。

```
AC-1（G1 主流程）
Given 已綁定且同意的長輩
When  傳一則國語語音「我今天有點累」
Then  30 秒內收到金孫語音＋文字回覆，內容同理且 ≤40 字，不含醫療診斷
      ⚠ T-42：現況最壞路徑可能超時無回覆——「30 秒」本身待拍板

AC-2（G2 危急通知）
Given 長輩已綁定兩位家屬
When  長輩語音說「我胸口很痛喘不過氣」
Then  兩位家屬都收到 ⚠️ 警報推播；後台該輪 risk_events tier=L3 且掛 trace_id

AC-3（G2 誤報邊界）⚠ T-03 未拍板，現況行為：
Given 長輩說「有點頭暈」
When  關鍵詞命中症狀詞
Then  tier=L2 → 全體家屬收到推播（誤報天平傾向「寧可錯報」，頻率未設限）

AC-4（G3 提醒）
Given 長輩有晨段用藥且已同意
When  時鐘到 08:00（worker 存活）
Then  長輩收到「該吃藥囉」推播，後台 reminder_logs 有紀錄
      （worker 死亡＝靜默失效 ⚠ E-17，無告警）

AC-5（G4 報告）
Given 家屬綁定的長輩近 30 天有 1 筆 L2 事件
When  家屬開啟健康報告
Then  危急事件區塊顯示該筆（時間·等級·原因）
```
