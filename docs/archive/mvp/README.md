# docs/mvp/ — MVP 階段文件組合

依老師《軟體開發實務文件系統指南》§14.1 的 MVP 文件組合，於 2026-07-06 由程式碼現況
**反向工程**產出。本專案為「程式先行」，因此這批文件的定位是：

1. **現況記錄（as-is）**：文件描述程式「實際上怎麼做」，每個宣稱可回溯到程式碼。
2. **決策帳本**：凡是 AI 開發時代為決定、人未拍板的事項，一律標 ⚠【待議 T-xx／E-xx】，
   對應 [全庫人工決策盤點-待議](../全庫人工決策盤點-待議.md)。
3. **回填後轉正**：團隊逐項拍板後，把決議改寫進對應文件，文件才轉為正向依據（to-be）。

| # | 文件 | 回答的問題 |
|---|------|-----------|
| 01 | [Product_Brief](01_Product_Brief.md) | 為什麼做、給誰用、成功怎麼衡量 |
| 02 | [Lean_PRD](02_Lean_PRD.md) | 要做什麼、驗收標準、未決事項佇列 |
| 03 | [User_Flow](03_User_Flow.md) | 使用者怎麼走（含全部分支與文案原文） |
| 04 | [Wireframe](04_Wireframe.md) | 畫面長什麼樣（LINE 對話劇本＋LIFF 線框） |
| 05 | [API_Spec](05_API_Spec.yaml) | 前後端／系統間合約（OpenAPI 3.1） |
| 06 | [DB_Schema](06_DB_Schema.md) | 資料模型、保留策略、Store 目錄 |
| 07 | [Tech_Design](07_Tech_Design.md) | 工程上怎麼組成（拓撲、管線、seams、設定） |
| 08 | [Test_Checklist](08_Test_Checklist.md) | 怎麼證明能用（分層、缺口、發布閘門） |
| 09 | [Release_Note](09_Release_Note.md) | 這版交付了什麼、已知問題 |

維護規則：改了 API／Schema／環境變數／對外行為，同步改對應文件（AGENTS.md 文件紀律）；
決議回填時在該文件把 ⚠ 標記改為決議內容並註記拍板人與日期。
