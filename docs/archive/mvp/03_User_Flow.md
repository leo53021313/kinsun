# 03 User Flow — 金孫 KinSun

> **文件性質**：2026-07-06 依程式碼現況反向工程的使用者流程（as-is）。每條流程含分支與
> **長輩／家屬實際看到的文案原文**。⚠ 標記對應 [全庫人工決策盤點-待議](../全庫人工決策盤點-待議.md)。
> 畫面細節見 [04_Wireframe](04_Wireframe.md)；驗收步驟見 [功能實測驗收清單](../功能實測驗收清單.md)。

**關鍵預設值**：`BINDING_GATE_ENABLED=true`（未綁定不可對話）、`LINE_TEXT_INPUT_ENABLED=false`
（預設只收語音）、`INVITE_TTL_HOURS=24`、`BINDING_SESSION_TTL_MINUTES=10`。

## 流程 1｜長輩傳語音訊息（主流程）

```
長輩按住麥克風說話
  → LINE POST /line/webhook（驗簽，失敗回 400 長輩端無回覆）
  → LineChannel.inbound：產 trace_id、下載音檔、上傳進站音檔備份
  → dispatch 閘門檢查
  → VoicePipeline：ASR → 危急偵測 → （L2↑先通知家屬）→ 金孫生成回覆 → TTS
  → 語音＋文字回覆（TTS_BACKEND=dgx）或純文字泡泡（bubble/失敗時）
```

1. **閘門分支**（`channels/inbound.py`）：
   - 未綁定／未同意 → 「金孫需要先完成綁定才能陪您聊天喔。請把家人給您的邀請碼貼到這裡，或回覆『設定』開始。」
   - 閘門檢查本身出錯 → **fail-open 放行** ⚠ T-10。
2. **ASR**（`speech/asr.py` → DGX Breeze-ASR-26）：
   - 失敗 → 「金孫剛剛沒聽清楚，您可以再說一次嗎？」——把系統故障說成聽不清楚 ⚠ T-37，
     且該輪**不做危急偵測** ⚠ T-13。
3. **危急偵測**（`safety/detector.py`，詳見流程 5）。
4. **金孫回覆**（`agent.py`）：人設 prompt「溫暖、有耐心的台灣長輩陪伴助理…最多兩三句、
   四十字內…不提供醫療診斷」⚠ T-35 未經人核定；記憶注入（今日對話＋長期記憶＋用藥／回診事實）；
   工具（天氣／時鐘／衛教 RAG）最多 3 輪。
   - 生成為空 → 「金孫剛剛想了一下沒講清楚，您可以再說一次嗎？」
   - LLM／記憶例外 → 「金孫剛剛沒聽清楚，您可以再說一次嗎？」（危急通知已先送出，不受影響）
5. **TTS 與遞送**（`speech/tts.py`＋`channels/inbound.py` VoiceReplyDelivery）：
   - 合成失敗／上傳失敗／發送失敗 → 一律退回文字泡泡（fail-safe，對話不中斷）。
   - `TTS_REPLY_TEXT=true`（預設）→ 語音＋文字並發。
   - ⚠ T-40：長語音無長度上限；⚠ T-42：webhook 同步跑完整管線，最壞 >115 秒，
     超過 reply token 效期＝長輩端永遠的沉默。

## 流程 2｜長輩傳文字訊息

1. 先進綁定流程比對（觸發詞「設定／綁定／選單」、邀請碼樣式自動辨識）→ 命中則走流程 3。
2. `LINE_TEXT_INPUT_ENABLED=false`（預設）→ 「金孫現在聽得懂語音喔，您可以按住麥克風跟我說說話。」
   **⚠ T-01：打字內容不進危急偵測——長輩打「救命」也只會收到這句。**
3. 開啟 debug 開關後，文字走與語音相同的管線（略過 ASR）。

## 流程 3｜帳號綁定（引導式對話）

**入口**：傳「設定」→ 數字選單（1 建立長輩檔案／2 邀請其他家屬／3 綁定貼碼／4 用藥選單／5 回診選單）。

**3a 建立長輩檔案**（家屬操作）：選 1 → 輸入長輩稱呼 → 系統建立長輩檔＋主要家屬關係，
產生長輩綁定碼：「已建立『X』的檔案…請把這組綁定碼交給『X』…{code}（24 小時內有效）」。

**3b 邀請其他家屬**：選 2 →（多位長輩時先選）→ 產生家屬邀請碼。

**3c 長輩貼碼綁定＋知情同意**：長輩貼上邀請碼（`^[A-Za-z0-9_-]{16,}$` 自動辨識）→ 確認步驟：

> 「您要綁定為『X』本人嗎？綁定後金孫會記錄您的對話，以提供關懷並在必要時通知家人。
> 同意請回覆『是』，取消請回覆『否』。」

- 回「是／好／確認」→ `redeem_invite(consent_by=SELF)`＋寫入 `consents`（version="1.0"
  ⚠ T-19 指向不存在的條款）→ 「綁定成功！您可以開始用語音跟金孫聊天囉。」
- ⚠ T-20：家屬拿長輩手機代操作也會被記成本人同意。
- ⚠ T-28：語音長輩的綁定**全程要打字**。

**失敗分支文案**：找不到這組邀請碼／已經被使用過了／已過期，請家屬重新產生一組／嘗試次數過多。
**逾時**：會話停留 >10 分鐘 → **靜默重置**（下句話當新對話）⚠ T-28。
**撤回同意**：服務層有 `revoke_consent` 但**無任何使用者入口**（API／LINE 指令皆未接）⚠ T-15。
**解除綁定／移除家屬／換手機重綁**：不存在 ⚠ T-25。

## 流程 4｜危急偵測與家屬通知（L0–L3）

1. **關鍵詞分級**（`safety/keywords.py`，⚠ T-02 詞表為 11 個 placeholder 國語詞）：
   - 絕對危險詞（救命／喘不過氣／胸口很痛／昏倒／想不開／不想活）→ 直接 L3。
   - 症狀詞（頭暈／跌倒／一直痛／好幾天沒睡／沒力氣）→ L2。
2. **LLM 分級**（Gemini，輸出 tier＋confidence＋reason）⚠ T-04 prompt 未審。
   - **LLM 失敗 → fail-safe 回 L0**：語意偵測靜默歸零且無人會知道 ⚠ T-05。
3. **合併**：`final=max(關鍵詞, LLM)`；L3 但 confidence<0.7 → 降 L2；L2 但 <0.4 → 降 L1
   （門檻寫死 ⚠ E-03）。
4. **L2 以上**：先落庫 `risk_events` → 立即推播**全體**已綁定家屬（無二次確認 ⚠ T-06、
   無去重／冷卻／上限 ⚠ T-07、`escalation_order` 未用 ⚠ T-26）：

   > 「⚠️【金孫關懷提醒】您關心的長輩可能需要您的注意：{reason}（風險等級 L2）。請盡快主動關心一下。」
   > L3 追加：「（如情況緊急，請自行評估是否撥打 119。金孫不提供醫療診斷。）」

   ⚠ T-08：無長輩姓名、會內插工程字串（reason）、L2/L3 幾乎同文。
5. **失敗分支**：查無家屬→只記 log；單一推播失敗→跳過續推下一位；全部失敗也只有一行 log
   （「送出」被當「送達」⚠ T-11）。
6. **危急當下對長輩的回覆**：無特別編排，仍走一般金孫生成——可能幻覺承諾「已叫救護車」⚠ T-09。

## 流程 5｜主動關懷（排程）

| 項目 | 早安問候 | 失聯關心 |
|------|---------|---------|
| 時間 | 每日 08:00 ⚠ T-33 | 每日 10:00，>2 天沒互動者 |
| 母體 | `memory.sessions()`（**所有**講過話的 LINE 帳號，不過同意閘門 ⚠ T-30） | 同左 |
| 訊息 | LLM 即席生成（意圖「早安問候，關心長者今天的狀況」），無模板兜底 ⚠ T-31 | 意圖「主動表達想念與關心」 |
| 落庫 | `reminder_logs`（proactive-greeting／proactive-care） | 同左 |

⚠ T-12：失聯 30 天＝連發 28 則想念關心，家屬毫不知情（無失聯升級通知）。

## 流程 6｜用藥提醒與回診提醒（排程）

**建資料**：家屬經 LIFF（[04_Wireframe](04_Wireframe.md)）或 LINE 選單 4／5。

**用藥**：每日 8／12／18／21 點各一次 ⚠ T-33（8 點與早安、回診疊發）。
文案「{長輩名}，{時段}該吃藥囉：{藥名、藥名}」；只發已同意長輩。
⚠ T-32：單次推播、**無確認機制**、job 失敗當天靜默放棄。

**回診**：每日 08:00，今明兩天的回診。
長輩（須同意）：「{name}，{今天/明天}要回診囉：{label}。記得準時，需要的話請家人陪您去。」
家屬（**無**同意守門）：「【金孫提醒】{name} {今天/明天}要回診——{label}。」
⚠ T-46：早診 8 點提醒會遲到；當天新增不會有提醒。

## 流程 7｜夜間整理與每日摘要（每日 03:00）

1. 逐長輩取**前一天整天**對話 → 寫入 mem0 長期記憶（provenance=self_claimed ⚠ T-21／T-22）。
2. 接著 LLM 產生當日對話摘要 → 存 `conversation_summaries`。
3. **功能缺口**：摘要**只落庫**，目前無任何推播或頁面呈現（健康報告不含它）⚠ T-18 拍板前暫無揭露面。
4. ⚠ E-13：資料源被 `MEMORY_MAX_TURNS=200` 截斷；⚠ E-14：worker 停機跨日＝該日對話永久不進長期記憶。
5. 同時段清理 job：TTS 音檔（03:30）、觀測五表（03:45）、進站音檔（03:00）。

## 流程 8｜家屬看健康報告（LIFF）

LINE 圖文選單「開啟家屬儀表板」→ LIFF 登入 → 長輩清單 → 健康報告
→ `GET /api/elders/{id}/health-report`（近 30 天）：

- 危急事件區塊：時間 · 等級（L2 警示／L3 緊急）· reason ⚠ T-17：reason 繞過 `can_view_transcript`。
- 提醒紀錄區塊：時間 · 類別（用藥／回診）· 內容。
- 空狀態「近 30 天無危急事件」⚠ T-47：長輩未綁定（未在監測）也顯示這句，呈現成「平安無事」。

