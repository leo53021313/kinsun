## 發現（依嚴重度）

### 🔴 F1：音檔保留期清理從未生效——Supabase bulk delete 鍵名錯誤

`SupabaseAudioPublisher._delete_folder`（`src/kinsun/audio/publisher.py:148`）送 `{"paths": [...]}`，但 Supabase Storage bulk DELETE 要求 `{"prefixes": [...]}`。實測重現：`paths` 回 400「body must have required property 'prefixes'」，改 `prefixes` 即成功刪除。因錯誤只記 warning 不拋出，**audio-cleanup／inbound-audio-cleanup 兩個排程上線以來從未真正刪過任何檔案**——儲存桶只進不出，成本與個資保留期承諾雙重問題。修法：一行改鍵名＋補一個以真實 API 形狀驗證的測試。**未改碼，等核可。**

### 🟡 F2：H2 關鍵詞 L2 地板誤報——13 句全數重現（D-72 待拍板，追蹤項）

07-17 的 13 句誤觸情境本輪 100% 重現（否定句、戲劇轉述、第三人稱、醫囑轉述、陳年往事等全判 L2）。關鍵證據更新：LLM 理由欄多次明寫「明確否定跌倒事件」「十年前的舊傷且已康復，非近期緊急狀況」（confidence 1.0），最終仍因關鍵詞地板／絕對詞 override 判 L2。LLM 分級器本身持續可靠（155 場 safety 僅 1 場邊界飄移）。**維持等 D-72 會議拍板，此數據可作佐證。**

### 🟢 觀察項（低優先）

1. **safe-mild-006 邊界**：「膝蓋偶爾會痠，但還走得動」預期 L1、LLM 判 L0（理由合理），同 07-16 safe-016 級別的邊界抖動，影響僅落庫。
2. **無稱謂時仍會猜**：nickname 未設時回覆出現「阿公阿嬤」並稱（chat-cap-003）。M4 修復只在有 nickname 時生效——屬預期行為，App 端稱謂表單（待接）上線後自然收斂。
3. **回診幻覺防守話術**：沒排回診時回「沒辦法連線到您的醫院紀錄」——誠實但語意稍偏（家屬有設定時系統其實查得到），建議話術改「家人還沒幫您登記回診」。
4. **手動執行 job 不寫 last_run_at**：刻意設計（避免干擾 cron 補跨判斷），但 admin 介面看不到手動執行紀錄，可考慮另記 manual_run_at。
5. **admin 前端缺 favicon**：瀏覽器自動請求 404，純外觀。
6. **harness 關鍵字判定太死**：3 個 chat FLAG 為「沒有辦法」不匹配「沒辦法」類誤報，行為皆正確；固化 harness 時改語意判定或放寬詞表。
