## 2. 三階段流程

- **階段 0（鳥瞰，1 輪）**：全庫快速掃描 → 產出「子系統分群表＋全景圖草稿」給 Leo 當地圖 → Leo 確認分群後才開始深潛。
- **階段 1～7（深潛，每群 1 輪）**，每群固定四步：
  1. 派開發包 agents（Explore 廣搜、architect 分析）深入研究該群程式碼；
  2. 主 agent 以白話講解：職責、關鍵類別、資料流、與其他群的介面；
  3. 展示要回填的文檔內容（草稿）給 Leo 看；
  4. Leo 確認 → 寫入文檔 → 一個 docs commit（Leo 分支，WHY/WHAT/IMPACT 格式）。
- **階段 F（收斂，1 輪）**：以累積的完整知識重畫 05 C4 與 17 §3 全景圖 → 跑跨文件一致性檢查 → 彙整發現清單交 Leo 決定後續工項。

## 5. 開發包（claude-Godzilla-z）運用方式

- **VibeCoding 模板＝驗收標準**：每章深度以對應模板要求為準（如 05「C4 嚴格版」、附錄一致性檢查表）。
- **開發包 agents＝研究工具**：Explore（廣搜）、architect（架構分析）、documentation-specialist（文檔輔助）；subagent 產出摘要依專案規則存入 `.claude/context/`。
- **講解由主 agent 主筆**（白話），agent 只做研究、不直接產出文檔正文。

## 6. Git 紀律

- 全程在 Leo 個人分支工作；不 push（等 Leo 明確指示）。
- 每群一個 `docs:` commit；規格文件本身單獨 commit。
- 不修改任何程式碼（含「順手修」）。
