# 全功能啟停腳本 — 設計

> 日期：2026-07-03　作者：Leo（整合負責人）＋ AI 代理
> 目標：一支腳本一鍵**啟動／關閉**金孫在 DGX Spark 上的完整服務堆疊。

## 一、動機

目前啟動整套服務要分別手動下多個指令（見 README §「啟動本機開發」與 `services/asr`、`services/tts` README）：ASR、TTS、Webhook、Scheduler、前端 dev server、ngrok，各自一個終端。開發／展示時反覆手動開關容易漏開、漏關、留孤兒程序。需要一支可信賴的啟停腳本降低操作成本與人為失誤。

## 二、範圍

### 納入管理的 6 個程序

| # | 程序 | 埠 | 啟動指令（自 repo 根目錄執行） | 執行環境 |
|---|------|----|----|------|
| 1 | ASR | 8001 | `services/asr/.venv/bin/python -m uvicorn services.asr.server:app --host 0.0.0.0 --port 8001` | 自帶 `services/asr/.venv`（Python 3.12） |
| 2 | TTS | 8002 | source `services/tts/.env.tts` 後 `"$TTS_PYTHON" -m uvicorn services.tts.server:app --host 0.0.0.0 --port 8002` | 外部 CosyVoice 環境（由 env 檔指定 `TTS_PYTHON`） |
| 3 | Webhook | 8000 | `uv run uvicorn --app-dir src "kinsun.app:build_app" --factory --port 8000` | 主 uv 環境；`.env` 由 `kinsun.config.load_dotenv` 自動載入 |
| 4 | Scheduler | — | `PYTHONPATH=src uv run python -m kinsun.scheduler` | 同上 |
| 5 | 前端 LIFF | 5173 | `npm --prefix frontend run dev` | Node / Vite |
| 6 | ngrok | — | `ngrok http 8000 --domain="$NGROK_DOMAIN"`（`NGROK_DOMAIN`／`NGROK_AUTHTOKEN` 取自 `.env`） | ngrok CLI |

### 範圍外（刻意不做，YAGNI）

- **不涵蓋 Windows/PowerShell**：整套含 GPU 服務只跑在 DGX（Linux/aarch64），與 repo「重模型只跑 DGX」一致。純前端／webhook 若要在 Win/mac 單獨開發，仍照 README 手動指令。
- 不做 systemd／daemon 化、不做自動重啟看門狗、不做多機分離部署編排。需要時再加。

## 三、腳本形式

單一入口 `scripts/kinsun.sh`，子指令：

- `scripts/kinsun.sh start` — 依序啟動全部（背景執行）。
- `scripts/kinsun.sh stop` — 全部關閉。
- `scripts/kinsun.sh status` — 列出各程序 PID／存活／埠健康。

採單檔＋子指令而非兩支獨立檔，是為了讓「程序清單」只維護一份（單一真實來源，DRY）。

## 四、背景執行、log 與 PID 機制

- 每個程序以 `setsid` 起在**獨立 process group**，`stdout`／`stderr` 導向 `logs/<name>.log`，PID 寫入 `.run/<name>.pid`。
- **啟動順序**：ASR、TTS（GPU、載模型較慢）→ Webhook → Scheduler → 前端 → ngrok。對 ASR／TTS 做短暫 `GET /healthz` 探測（有 timeout），僅為在總結印出健康狀態，不硬性阻擋後續啟動。
- **冪等**：若 PID 檔存在且程序仍存活 → 跳過不重複起；啟動前檢查目標埠是否已被占用，占用則跳過並提示。
- **stop**：讀 PID 檔，對整個 process group 送 `SIGTERM`（一併收掉 npm→vite、uvicorn 子程序、ngrok 子程序，避免孤兒），逾時未退再送 `SIGKILL`，最後刪除 PID 檔。

## 五、錯誤處理與「缺就跳過」

- `start` 前先檢查：位於 repo 根、必要工具存在（`uv`、`npm`、`ngrok`、`services/asr/.venv`），訊息明確可辨識。
- **可選元件缺 → 警告但不中斷整體**：
  - `services/tts/.env.tts` 不存在 → 跳過 TTS，提示照 `services/tts/.env.tts.example` 建立。
  - `frontend/node_modules` 缺 → 跳過前端，提示先 `npm --prefix frontend install`。
  - `.env` 無 `NGROK_DOMAIN` → 提示並改用 ngrok 臨時網域（`ngrok http 8000`）。
- 任一程序啟動後短時間內即死亡 → 明確指出是哪個程序、log 檔路徑。

## 六、附帶產物

- `services/tts/.env.tts.example` — TTS 變數範本（`TTS_PYTHON`、`TTS_MODEL_ID`、`TTS_COSY_DIR`、`TTS_MATCHA_DIR`、`TTS_PROMPT_WAV`、`TTS_PROMPT_TEXT`、`TTS_PRELOAD`），每項附一行中文註解。
- 更新 `.gitignore`：忽略 `logs/`、`.run/`、`services/tts/.env.tts`。
- Webhook 是否加 `--reload`：預設**關**；以環境變數 `KINSUN_RELOAD=1` 開啟（背景執行 reload 會持續監看檔案、且多一層子程序，故預設關）。

## 七、驗證方式

- `bash -n scripts/kinsun.sh` 語法檢查；有 shellcheck 則一併過。
- 執行 `scripts/kinsun.sh status`（無副作用）確認未啟動時正確報告全部停止。
- `start`／`stop` 屬對外（ngrok 公開）與觸及雲端（webhook 建表），交由使用者在需要時實跑驗證。
