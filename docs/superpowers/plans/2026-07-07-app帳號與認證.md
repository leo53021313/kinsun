# App 帳號與認證（階段 2）實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App 的帳號地基：家屬 email＋密碼註冊登入、長輩以綁定碼換裝置 token、統一的 API token 發放與驗證——全部脫離 LINE。

**Architecture:** 帳號領域（`accounts/`）擴充兩張表（`guardian_accounts`、`api_tokens`）與服務方法；密碼雜湊獨立小模組（標準庫 `hashlib.scrypt`，零新依賴）；HTTP 層新增 `web/app_api.py` 三個端點。長輩綁定重用既有 `invites` 機制——`redeem_invite` 加 `channel` 參數（預設 `Channel.LINE` 不破壞既有呼叫端），App 路徑以新產的 app 帳號識別寫入 `channel_bindings(channel='app')`。token 為不透明隨機字串，DB 只存 SHA-256 雜湊（可撤銷＝刪列；不引入 JWT）。

**Tech Stack:** Python 標準庫（`hashlib.scrypt`／`secrets`／`hmac`）、FastAPI（既有）、pytest。無新依賴、無新環境變數。

## Global Constraints

- 同前計畫（繁中全形標點、命名規範、三件套＋合約測試、每 Task 全綠才 commit）。
- 設計源頭：spec §4.2。
- 安全紀律：密碼以 scrypt（n=2¹⁴、r=8、p=1、隨機 16B 鹽）雜湊；登入失敗不區分「帳號不存在／密碼錯」；比對一律 `hmac.compare_digest`；token 明文只在回應出現一次、DB 僅存雜湊；email 正規化 `strip().lower()`。

### Task 4: HTTP 層（三端點）＋組裝

**Files:** Create `src/kinsun/web/app_api.py`；Modify `src/kinsun/app.py`（掛載）；Test `tests/test_api_app_auth.py`。

**Interfaces（Produces）:** `create_app_api_router(*, accounts: AccountService) -> APIRouter`（prefix `/api/app`）：

| 端點 | 請求 | 成功 | 失敗 |
|---|---|---|---|
| `POST /api/app/guardians` | `{email, password, name}`（密碼 ≥ 8 碼） | 201 `{guardian_id, name, token}` | 409 email_taken |
| `POST /api/app/sessions` | `{email, password}` | 200 `{guardian_id, name, token}` | 401 invalid_credentials |
| `POST /api/app/device-bindings` | `{code}` | 201 `{elder_id, name, token}` | 404 not_found；409 used/expired/too_many_attempts |

錯誤 body 統一 `{"detail": "<reason>"}`（FastAPI 慣例）。token 驗證中介（`Depends`）本階段先提供 `current_app_guardian` 依賴（供階段 3 家屬 REST 換認證用），本階段僅以單元測試驗證。
