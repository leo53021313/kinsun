# docs/dev 架構文檔深化執行計畫

> **For agentic workers:** 本計畫含「Leo 確認閘門」（每群回填前必須取得 Leo 核可），**必須在主對話中以 superpowers:executing-plans 內聯執行**，不得整包交給 subagent 跑完；subagent 僅用於各任務內的程式碼研究步驟。步驟用 checkbox（`- [ ]`）追蹤。

**Goal:** 逐子系統深入研究重構後的程式碼，把研究成果回填 docs/dev 既有文檔（05／09／10／12／17），最終重畫全景架構圖，使文檔深度達到 VibeCoding 模板要求。

**Architecture:** 三階段——階段 0 鳥瞰（分群表＋草稿圖給 Leo 確認）→ 8 個深潛輪（群 2 依 Leo 決議拆 2a 記憶／2b 知識檢索；每輪研究→白話講解→Leo 確認→回填 commit）→ 階段 F 收斂（重畫 05 C4 與 17 §3 全景圖＋跨文件一致性檢查）。

**05 §8 章節錨點總表（凍結，2026-07-10 Leo 核定分群後）：** 8.1 語音對話鏈路｜8.2 記憶｜8.3 知識檢索（RAG）｜8.4 健康領域｜8.5 安全與主動關懷｜8.6 帳號綁定與同意｜8.7 平台底座。

**Tech Stack:** Markdown＋Mermaid；研究工具＝開發包 agents（Explore／architect／documentation-specialist）；規格＝[2026-07-10-架構文檔深化-design.md](../specs/2026-07-10-架構文檔深化-design.md)。

## Global Constraints

- **純文檔**：不修改 `src/`、`app/`、`frontend/`、`services/`、`shared/`、`scripts/` 下任何檔案；發現代碼問題只登記。
- **不新增 docs/dev 文件**：成果只回填既有五份（05／09／10／12／17）；發現清單登記進 05「差距與重構項」（群 7 登記進 12 §9）。
- **Leo 確認閘門**：每群「寫入文檔」前必須先展示草稿並取得 Leo 明確核可（AskUserQuestion 或對話確認）；草稿一律先寫 scratchpad，不直接改 docs。
- **Git**：全程 Leo 分支、不 push；每群一個 `docs:` commit，訊息含 WHY／WHAT／IMPACT。
- **語言**：台灣繁體中文＋全形標點（AGENTS.md）。
- **Subagent 摘要**：architect／Explore 研究產出依專案規則摘要存入 `.claude/context/decisions/`，檔名 `{agent}-{YYYY-MM-DD-HHmm}-{主題}.md`。
- **驗收標準**：各章深度以老師模板為準——`claude-Godzilla-z/VibeCoding_Workflow_Templates/` 的 05（C4 嚴格版）、09、10、12、17 對應章節要求。
- **標準研究七問**（每群深潛的 agent 研究提綱，逐群共用）：
  1. 模組職責與邊界是什麼？跟文檔宣稱的一致嗎？
  2. 公開介面有哪些（Protocol／API 端點／資料表）？
  3. 關鍵資料流怎麼走（正常路徑＋錯誤路徑）？
  4. 與其他群的耦合點在哪（import 了誰、被誰 import）？
  5. 命名與 AGENTS.md 規範的符合度？
  6. 測試現況（對應 test 檔、合約測試有無）？
  7. 發現了什麼問題（潛在 bug／死碼／邊界不清，附檔案:行號＋嚴重度）？
- **深潛任務標準六步**（任務 1～7 共用骨架，各任務只列參數差異）：
  ① 派 Explore（廣搜該群檔案）＋architect（分析架構）雙 agent 研究，prompt 帶標準研究七問＋該群特定問題
  ② agent 摘要存 `.claude/context/decisions/`
  ③ 對話中白話講解（職責／關鍵類別／資料流／跨群介面）＋展示回填草稿（草稿存 scratchpad）
  ④ Leo 核可（有意見→修草稿→再確認）
  ⑤ 寫入文檔指定章節錨點
  ⑥ 驗證後 commit：`grep` 確認新章節存在、mermaid 圍欄配對（```` ```mermaid ```` 與 ```` ``` ```` 數量相等）、與 09 分層圖無矛盾
