# 記憶檢索延遲優化 實作計畫（工項 ①②）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓三路排程事實只查一次資料庫（現為三次相同查詢），並依實測決定要不要調升連線池上限。

**Architecture:** `ScheduleFacts` 由「一個 kind 一個實例、各查一次」改為「一個實例查一次、回傳三段」。為此 `FactProvider` 的回傳型別擴充為 `FactSection | list[FactSection] | None`，`_gather_facts` 展開多段後仍按 provider 註冊順序排列。段落內容、標題、順序一字不變。

**Tech Stack:** Python 3.12、psycopg/psycopg_pool、pytest、ruff。無新增依賴。

**Spec:** `docs/superpowers/specs/2026-08-07-記憶檢索延遲優化-design.md`

## Global Constraints

- **段落標題與行文一字不可變**：`_TITLES` 三個字串、`_line` 的組字方式全部原樣保留。那是 prompt 契約，`test_schedules_facts.py`／`test_schedules_wording.py` 守著。
- **段落順序是 prompt 契約**：時間 → 用藥 → 回診 → 自訂 → 守則 → 位置。見 `recall._gather_facts` 的 ⚠️ 說明（「不可改用誰先回來就先放」）。
- **某個 kind 沒有排程時，該段必須缺席**，不可變成空段或「一段包三種」。
- **不動寫入路徑**：`record_turn`、夜間整理批次、`schedules` 的任何寫入一字不改。
- **連線池上限**：Supabase Supavisor pool 上限 25，常駐 4 進程（`WEB_WORKERS=2`＋scheduler＋rag_worker）。`DATABASE_POOL_MAX_SIZE` 建議值 **5**（4×5=20，留 5 條餘裕）；**不採 6**（4×6=24 太貼上限，2026-07-30 曾因連線饑荒讓排程器靜默停擺）。
- **一次只跑一支 pytest**：併行跑會清空共用測試庫（既有教訓）。
- **測試指令一律用 `.venv/bin/python -m pytest`**（專案採 src layout，`pythonpath` 已在 `pyproject.toml` 設好）。
- **語言**：程式碼註解、docstring、commit 訊息一律台灣繁體中文，全形標點。

```python
def _sections_of(future) -> list[FactSection]:
    """取一路事實的結果，一律正規化成清單。

    提供者可回單段、多段（`ScheduleFacts` 一次查詢供用藥／回診／自訂三段）或
    `None`／空清單（該段缺席）。等太久同樣視同缺席（見 `_gather_facts` 的
    ⚠️ 說明）——`fetch` 本來就允許回 None，逾時不是錯誤。
    """
    try:
        result = future.result(timeout=_FACT_TIMEOUT_SECONDS)
    except FuturesTimeoutError:
        logger.warning("事實提供者逾時（%.1f 秒），略過該段", _FACT_TIMEOUT_SECONDS)
        return []
    if result is None:
        return []
    return list(result) if isinstance(result, list) else [result]
```

```python
class ScheduleFacts:
    """facts(elder_id) -> list[FactSection]（三種 kind 各一段，無排程的 kind 不出現）。

    **一次查詢供三段**：三種 kind 的資料來自同一個 `list_for_elder(elder_id)`，
    先前一個 kind 一個實例、各打一次完全相同的查詢，三次跨海往返只是白等
    （單次往返實測約 250ms，2026-08-07）。段落仍維持三段獨立——標題本身就在
    告訴模型「這是藥」「這是回診」，併起來等於把分類資訊丟掉。

    以 `group_id` 收斂：同一件事的多個鬧鐘（早晚兩次的藥、前一天加當天的回診）
    注入時必須合成一行，否則模型會以為那是兩種藥、兩次回診。
    """

    def __init__(self, store: ScheduleStore, *, clock: Callable[[], datetime]) -> None:
        self._store = store
        self._clock = clock

    def facts(self, elder_id: str) -> list[FactSection]:
        rows = self._store.list_for_elder(elder_id)
        sections = []
        for kind in _KIND_ORDER:
            section = self._section(kind, rows)
            if section is not None:
                sections.append(section)
        return sections

    def _section(self, kind: ScheduleKind, rows: list[Schedule]) -> FactSection | None:
        matched = [s for s in rows if s.kind == kind]
        if not matched:
            return None
        groups: dict[str, list[Schedule]] = {}
        for row in matched:
            groups.setdefault(row.group_id, []).append(row)
        items = [self._line(kind, group) for group in groups.values()]
        return FactSection(_TITLES[kind], items)

    def _line(self, kind: ScheduleKind, group: list[Schedule]) -> str:
        first = group[0]
        if kind == ScheduleKind.MEDICATION:
            labels = "、".join(slot_label(int(s.repeat_time[:2])) for s in group if s.repeat_time)
            return f"{first.title}（{labels}）"
        tz = self._clock().tzinfo
        if kind == ScheduleKind.APPOINTMENT:
            when = first.event_at if first.event_at is not None else first.scheduled_at
            date = datetime.fromtimestamp(when, tz).date().isoformat() if when else ""
            return f"{date} {first.title}".strip()
        return f"{self._when_phrase(first, tz)} {first.title}".strip()
```
