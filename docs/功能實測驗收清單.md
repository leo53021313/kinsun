## 0. 測試前必讀

- **綠燈 ≠ 真整合可行**：`uv run pytest`（618 passed / 61 skipped）全是離線注入 fake，**驗不到** App↔後端↔Gemini／Supabase／mem0／DGX ASR／TTS 的真串接。本清單專驗真整合。
- **這台機器＝DGX Spark**（aarch64 / GB10），真 ASR／TTS 模型在本機跑；後端與 App 開發伺服器也在本機。
- **主線是 App**：長輩端＝App 對講機（按住說話）、家屬端＝App 管理介面。LINE 端凍結維運，只做煙霧測試（D 區）；LIFF 已被 App 取代。
- **內測模式已開**（`.env`）：`INTERNAL_TESTING_ENABLED=true` → App 顯示「切換身分」（RoleSwitcher，一機雙端）＋觀測後台開放排程手動觸發；`ASR_DEBUG_SHOW_TRANSCRIPT=true` → 金孫回覆前附 ASR 辨識原話；`BINDING_GATE_ENABLED=true` → 未綁定不能對話（正式行為）。
- **實測時全程開著觀測後台**（E 區），每一輪的 ASR→LLM→TTS→回覆延遲與錯誤都看得到，抓問題靠它。
- **回報格式**：每項填「負責人／日期／結果（✅通過 / ❌失敗 / ⏭跳過）／備註（失敗貼 trace_id 或 log）」。

## 1. 環境啟動 Runbook（Leo 或整合負責人先做）

### 1.1 後端全套（ASR:8001／TTS:8002／Webhook:8000／Scheduler／ngrok）

```bash
cd /home/leo29/kinsun
scripts/kinsun.sh start     # 背景啟動全部；GPU 服務先起（載模型較慢）
scripts/kinsun.sh status    # 看各服務 PID／埠／健康
scripts/kinsun.sh stop      # 測完關閉
# log 在 logs/<service>.log；驗證：
#   curl -s http://127.0.0.1:8000/healthz   → {"status":"ok"}
#   curl -s http://127.0.0.1:8001/healthz   → {"status":"ok","model_loaded":true}
#   curl -s http://127.0.0.1:8002/healthz   → {"status":"ok","model_loaded":true}
```

> ⚠️ ngrok 一開，後端即對外（App 與 LINE webhook 都走 `https://cranial-bloomers-appealing.ngrok-free.dev`），
> 並產生真 Gemini 呼叫；測完即關。

### 1.2 App（Expo Go，手機實機）

```bash
cd /home/leo29/kinsun/app
npx expo start              # 手機 Expo Go 掃終端機 QR；電腦手機需同網段
npx expo start --tunnel     # 不同網段改用 tunnel
```

手機需先裝「Expo Go」（App Store／Play 商店）。`app/.env` 的 `EXPO_PUBLIC_API_URL` 已指向 ngrok 網域，
手機不必與 DGX 同網段也連得到後端（Expo 連線本身仍需同網段或 tunnel）。

### 1.3 觀測後台（admin）

瀏覽器開 `http://127.0.0.1:8000/admin/`（或 `https://<ngrok 網域>/admin/`），金鑰＝`.env` 的 `ADMIN_API_KEY`。

### 1.4 LINE webhook（僅測 D 區才需要）

LINE Developers → Messaging API → Webhook URL 設
`https://cranial-bloomers-appealing.ngrok-free.dev/line/webhook`，Verify 應回 Success、Use webhook = ON。

## 4. 已知限制與缺口（實測時預期會遇到，非 bug）

- **推播未接（階段 5）**：家屬通知（含危急警報）要**開 App** 才看得到；正式上線前需 Apple Developer 帳號＋EAS build。
- **危急通知失敗無感知（庚-02 待辦）**：L2 通知若發送失敗只留 `delivered=False`，admin 不會主動告警——實測期間請在長輩詳情「危急通知」分頁人工核對送達。
- **錯誤路徑有字無聲（庚-11 待辦）**：pipeline fallback 與 TTS 降級只回文字，語音優先的長輩會「有字無聲」。
- **金孫參考語音未定調**：TTS 仍為 CosyVoice 範例聲；台語 TTS 微調在另專案進行。
- **mem0 + Supabase 不支援 BM25**：長期記憶僅語意檢索。
- **台語**：ASR 可收台語（Breeze-ASR-26 國台語），TTS 回覆為國語；台語回覆是後續工作。
- **LIFF 凍結**：LINE Login channel 未設，D3 跳過。
